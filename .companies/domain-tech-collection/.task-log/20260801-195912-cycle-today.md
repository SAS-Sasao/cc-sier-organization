## 発見した問題（要対応）

### feedback メモリが Case Bank に統合されていない

`failure_patterns: 0` となっており、Read フェーズで失敗パターンが参照されない状態。

原因: `rebuild-case-bank.sh` L344 が `feedback_*.md`（**アンダースコア**）を glob しているが、実在するファイルはいずれもマッチしない。

| 場所 | ファイル名 | マッチ |
|---|---|---|
| `~/.claude/projects/.../memory/` | `cc-sier-design-review-lessons.md` | ✗ プレフィックスなし（frontmatter は `type: feedback`） |
| `~/.claude/projects/.../memory/` | `claude-code-spec-reference-errors.md` | ✗ 同上（`type: reference`） |
| `docs/research/.claude/agent-memory/system-architect/` | `feedback-verify-review-numbers.md` | ✗ **ハイフン**区切り |

影響: `/company-evolve` の Read フェーズ（secretary.md 起動時に失敗パターンを注入する仕組み）が機能しない。
学習した失敗パターンが蓄積されても次セッションで参照されないため、同じ失敗を繰り返しうる。

対応案:
1. `rebuild-case-bank.sh` の glob を `feedback[-_]*.md` に拡張し、加えて frontmatter の `type: feedback` も判定に加える（根本対応）
2. メモリファイル名を `feedback_` プレフィックスに統一する（運用対応）

**1 を推奨**。ファイル名規約に依存すると、今後も命名のたびに漏れる。
