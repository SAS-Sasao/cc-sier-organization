## 判断 2: C11 / C12 を新設（ゲートとローダの包含関係）

Issue が「本題ではない」として提起した関連点に方針を出した。

**問題**: C1〜C10 はローダのバリデーション（実装設計 §3.3 の V1〜V13）の**真部分集合**であり、
V9（上位業態の参照先実在）/ V10（参照の循環なし）/ V11（別名が空でない）/ V12（別名の重複なし）
に対応する C 番号がない。段階 0 の完了条件は「実装前にカタログ側の不整合を出し切る」ことなので、
ゲートがローダより緩いと「**hook は緑なのに実行すると止まる**」状態を段階 0 が見逃す。

**採用しなかった案**: C 番号を V 番号に 1:1 で増やす。
理由: ローダ側に V14 以降が追加されるたび同じ乖離が再発する。
**今回の C4 欠落がまさにその形で発生した**ため、同じ構造を温存すべきでないと判断した。

**採用した案**: ローダ自身を検査の最後に通す（C12）。
包含関係をコードの重複なしに保証できる。実装側の暫定対応（C12）と一致。

**C1〜C11 を先に評価する理由**も明記した: ローダは最初の `CatalogError` で停止するため、
列欠落のような自明な不備がある状態で実行すると理由コードが 1 件しか得られない。
C1〜C11 は独立に全件評価できるので、編集者に一度で全ての不備を返せる。

あわせて C11（発表主体対応表への写像）を追加。実装側の暫定対応を正式化したもの。
