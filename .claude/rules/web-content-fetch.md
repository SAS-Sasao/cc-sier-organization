# Web コンテンツ取得ルール

外部 URL の内容を解析・要約する際の取得方法。CLAUDE.md 本体から @参照。

## 原則: 解析依頼では curl で原文を取得する

**オーナーから URL を渡されて「要約して」「解析して」「読んで」と依頼された場合、原則として `curl` で原文を取得する。**

`WebFetch` は信頼ドメイン外のページについて、**中間 LLM が数百字に圧縮した要約**をメインモデルに渡す。この経路では以下が失われる。

- 記事内の**一次情報へのリンク**（著者が根拠として挙げた外部 URL）
- **具体的な数値の文脈**（何を分母にした数字か等）
- **原文の表記**（`opus5` が `Opus 5` に正規化される等。後から grep で照合できなくなる）

さらに、ページの**フッターやナビゲーションを記事内容と誤認**することがある（実測で `Zenn` / `GitHub` / `X (Twitter)` が記事の固有名詞として返された）。

根拠: `.companies/domain-tech-collection/docs/insights/analyses/webfetch-summarization.md`（2026-08-02 実測検証、主張 5 件を実証）

## 判断基準

| 対象 | 取得方法 | 理由 |
|---|---|---|
| **技術記事プラットフォーム**（Zenn / Qiita / note / はてブ / 個人ブログ / ニュースサイト） | **curl 必須** | 確実に要約経路を通る |
| **公式ドキュメント**（`docs.aws.amazon.com` / `docs.python.org` / `developer.mozilla.org` / `react.dev` / `kubernetes.io` 等） | WebFetch 可 | 信頼ドメインとしてバイパスされ生 Markdown が返る |
| 判断がつかない | **curl** | 迷ったら原文。コストは数秒 |

**注意**: 信頼ドメインは 80 以上あるとされるが、**完全なリストは未確認**。本組織で実測確認したのは `docs.aws.amazon.com` のみ。`aws.amazon.com`（ブログ・What's New）は**対象外**である点に注意。

### WebFetch でも原文が返る場合の副作用

信頼ドメインのバイパス経路では、**prompt による絞り込みが効かない**。「H2 の見出しのみ」と指示しても全文が返る。要約が欲しい場合は取得後に自分で絞ること。

## 実行手順

### 1. 取得

```bash
curl -sL --max-time 30 -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)" \
  "{URL}" -o /path/to/scratchpad/raw.html
```

- `-L` リダイレクト追従
- `--max-time 30` タイムアウト（長いページでも 30 秒で足りる）
- **User-Agent は必須**。付けないと 403 を返すサイトがある
- 保存先はスクラッチパッド（`/tmp/claude-*/…/scratchpad`）。リポジトリを汚さない

### 2. 本文抽出

```python
import re
h = open('raw.html', encoding='utf-8', errors='ignore').read()
h = re.sub(r'(?is)<(script|style|noscript)[^>]*>.*?</\1>', ' ', h)   # 先にスクリプト除去
t = re.sub(r'(?s)<[^>]+>', ' ', h)                                    # タグ除去
t = re.sub(r'&[a-z]+;|&#\d+;', ' ', t)                                # 実体参照
t = re.sub(r'\s+', ' ', t).strip()                                    # 空白圧縮
```

`script`/`style` を**先に**除去すること。後回しにすると JS のコードが本文に混入する。

### 3. 読む

抽出したテキストを分割して**全文読む**。文字数を確認し、長ければ複数回に分けること。

```bash
wc -m text.txt          # 文字数を確認
```

## 失敗時の対処

| 症状 | 対処 |
|---|---|
| HTML は取れるが本文が入っていない | SPA の可能性。`data-*-props` 等の JSON 埋め込みを探す。無ければ WebFetch にフォールバックし、**要約経由であることを明示して報告** |
| 403 / 401 | 認証が必要。`gh` CLI や MCP サーバーが使えないか検討。使えなければオーナーに報告 |
| タイムアウト | `--max-time` を延ばす前に、URL が正しいか確認 |
| 文字化け | `errors='ignore'` で読み、それでも駄目なら `chardet` 相当の判定を挟む |

**curl が使えなかった場合、WebFetch にフォールバックしてよい。ただし報告時に「要約経由のため一次情報リンクや数値の文脈が落ちている可能性がある」と明示すること。** 黙って要約を原文として扱わない。

---

## 報告時の注記

curl で取得した場合、報告に取得方法と文字数を含める。読み手が「原文を読んだ結果か、要約を読んだ結果か」を判別できるようにするため。

```
curl で原文を取得しました（12,458 字）。
```

## 適用範囲

### 適用する

- オーナーからの「要約して」「解析して」「読んで」「調べて」の依頼
- 記事内容を成果物（レポート・設計書）の根拠にする場合
- 記事の主張を検証する場合

### 適用しない（WebFetch でよい）

- URL の生死確認だけが目的の場合
- ページタイトルのみ必要な場合
- 公式ドキュメントの参照（信頼ドメイン）

### 日次ダイジェストについて

`wf-daily-digest` の巡回 8 ソースは**すべて信頼ドメイン外**であり、現状は二重要約になっている。
curl 主体への切り替えは未実施（影響範囲の見積もりが必要なため保留）。
詳細と対応案は検証レポート §6 を参照。
