0. 3 行で

  • 2026 年 8 月から、Claude が出力するテキストには「AI が作った印」が見えない形で埋め込まれている。
  • その印は文章の意味も品質も変えない。専用の鍵を持つ人だけが「Claude が関わった可能性が高い」と判定できる。
  • ただし 「AI が書いた証拠」にはならないと Anthropic 自身が繰り返し明言している。人間の文章を校正させただけでも印は付く。

1. そもそも「電子透かし」とは（初心者向け）

1.1 紙のお札の例え

一万円札を光に透かすと、印刷では見えない人物像が浮かびます。普通に使う分にはまったく気づかないが、確かめ方を知っている人には確かめられる。 これが電子透かし（ウォーターマーク）の考え方です。

デジタルの世界では、画像に対しては昔から使われてきました。写真の画素の色を人間には分からないレベルで微妙にずらせば、見た目は変わらないのに機械には読み取れる情報を埋め込めます。

1.2 でも「文章」は難しかった

画像にはずらせる余地があります。赤色の濃さを 200 から 201 にしても誰も気づきません。

ところが文章にはそれがありません。 「猫」を「犬」に変えたら意味が変わってしまう。1 文字ずらすということができないのです。

記事の著者は 2023 年にこの研究アイデアを聞いたとき、こう思ったと書いています。

当時の正直な感想は「面白いけど、実用化は無理だろう」というものでした。

その 3 年後、Google も Anthropic も実運用に載せた。何が変わったのかを追ったのがこの記事です。

2. 仕組み — 「どちらでもいい場面」に印を埋める

2.1 AI は毎回サイコロを振っている

まず前提として、LLM（Claude や Gemini）は次の単語を確率で選んでいます。

「今日は天気が」の続きとして……
   良い   40%
   悪い   25%
   崩れる 15%
   ...

そして文章の中には、「どちらを選んでも自然」という場面が何度も出てきます。 「これは」でも「それは」でも通じる、というような箇所です。

2.2 その「どちらでもいい」を、鍵で少しだけ偏らせる

透かしの原理はここにあります。

どちらでもよい選択を、秘密鍵から導いたルールでほんの少し偏らせる。

1 回の選択では何も分かりません。ですが数百単語ぶん集計すると、人間が書いた文章では統計的にあり得ない「癖」が浮かび上がります。

紙のお札が「光に透かす」で確かめられたように、文章は「単語の選ばれ方を集計する」で確かめられる、というわけです。

2.3 最初の手法（2023 年）とその弱点

出発点は KGW 法（Kirchenbauer らの論文の頭文字）です。

  1. 語彙を「グリーンリスト」と「レッドリスト」に二分する（分け方は秘密鍵で決まる）
  2. 生成時にグリーンリストの単語を少しだけ選ばれやすくする
  3. 検出時は「グリーンリストの単語が全体の何割か」を数える。偶然では説明できない割合なら AI 生成と判定

モデルの中身を見なくても、秘密鍵さえあれば検出できるのが利点でした。

ただし弱点が 2 つありました。記事はこの 2 つを軸に話を進めます。

#弱点中身
1品質が落ちる本来選ばれにくい単語を無理に選ばせるので、文章が不自然になる
2言い換えると消える別の AI に「言い換えて」と頼めば、単語が総入れ替えになり印が消える

3. 弱点①「品質が落ちる」をどう解いたか

3.1 発想の転換 — 「選び方」ではなく「サイコロ」を差し替える

品質を落とさずに透かしを入れる手法群を distortion-free（歪みなし） と呼びます。代表が Gumbel-Max トリック です。

考え方はこうです。

  • 従来: 選ばれる確率そのものをいじる → 分布が歪む → 品質が落ちる
  • 新しい方法: 確率はそのまま。サイコロの出目の作り方だけを差し替える

AI は元々「乱数」を使って単語を選んでいます。その乱数を、本物のランダムから「秘密鍵から計算した疑似ランダム」に置き換えるのです。

どの単語がどの確率で選ばれるかは元とまったく同じまま、検出者だけが「この文章の単語は、鍵から作った乱数と相関している」と確かめられる。

3.2 公式が使った例え — モノポリーと円周率

Anthropic の公式ブログにある比喩が非常に分かりやすいので引用します。

モノポリーで、サイコロを振る代わりに円周率の数字の並びを使うとします。小数点以下100万桁目あたりから始めて、以降は各プレイヤーが次の桁を「出目」として使う。プレイ体験は何も変わりませんし、ゲームの結果にも影響しません。しかし後から全ての手を並べて円周率と照合すれば、「この試合は円周率を使っていたらしい」と判定できます。

記事の著者はこうまとめています。

くじの公平さは保ったまま、くじの中身だけを検出者が答え合わせできる状態にしている。

3.3 実運用に到達した SynthID-Text（Google）

Google DeepMind が Gemini で実運用している手法です。2024 年に Nature 誌に載りました。

Tournament sampling という方式で、候補の単語を何本か引いてきて、秘密鍵で決まる判定基準による勝ち抜き戦を行い、勝った単語を出力します。

Gumbel-Max ではなくこちらを選んだ理由が実務的です。Gumbel-Max は決定的になってしまう（同じ文脈からは常に同じ単語が出る）ため、同じ質問を何度しても似た答えばかりになり、チャット製品として使いにくいのです。Tournament sampling は本物のサンプリングを残しているので、毎回違う答えが出せます。

2,000 万件規模の本番トラフィックで評価した結果まで論文に含まれています。著者はこう書いています。

「実用化は無理だろう」という2023年の自分の予想は、この論文でほぼ完全に否定されたことになります。

4. 弱点②「言い換えると消える」は、まだ解けていない

こちらが本命の弱点です。

透かしの実体は「表層の単語の選ばれ方の偏り」です。別の AI に「この文章を言い換えて」と頼むと、意味は保たれたまま単語が総入れ替えになり、印は薄まって消えます。

2023 年の時点で「言い換え専用モデルを 1 回通すだけで既存の検出器がほぼ全滅する」ことが実証されています。

研究側の応戦 — 意味の空間に埋める

対策として、印を埋める場所を単語から「意味」へ移す方向が研究されています。

手法考え方
SemStamp（2024）文を「意味のベクトル」に変換し、秘密鍵が指す領域に入る文だけを採用する。言い換えても意味は近い位置に留まるので、印が生き残る
PASA（2026）品質を落とさないことと言い換えに強いことを、理論的に両立させたと主張

ただしこれらはまだ研究段階で、商用製品には載っていません。

5. で、Claude はどうなのか

5.1 答えは公式から出た

記事は当初「Anthropic は技術的詳細を公開していない」と書いていましたが、公開直後に Anthropic の公式ブログが出て答え合わせがされました（記事は 08-15 に追記）。

Claude's text watermark is a version of the SynthID-Text approach published by Google DeepMind in a Nature paper in 2024.

Claude の透かしは、Google の SynthID-Text の一種でした。§3.3 で説明した Tournament sampling の系統です。

項目内容
開始時期2026 年 8 月 2 日以降にリリースされたモデル
適用範囲EU 圏内に限らず世界中
経緯EU AI Act 第 50 条の透明性規範に署名したことに伴う
埋め込み位置モデルレベル（アプリ・API など経路を問わず全出力に入る）
速度・価格変わらない（生成トークン数が増えないため）
品質内部テストで内容・創造性・読みやすさへの影響は見られなかったとしている
検出手段検出 API を近く提供予定（2026-08-16 時点で未公開）

5.2 ここが最重要 — 「AI が書いた証拠」にはならない

Anthropic 自身が繰り返し釘を刺しています。

鍵で答えられるのは「Claude が部分的に関与した尤度」だけで、人間が書いたことの確認にも、別の AI が書いたかの判別にも使えない

公式ブログには What does a watermark actually prove? という項があり、「Claude が書いた」と「Claude が大幅に編集した」を区別できないと明記されています。

具体的には次のような限界があります。

状況透かしはどうなるか
短いテキスト信号が足りず検出できない（選択の機会が少ないため）
事実を述べる箇所薄くなる。「ニュートンの主著は Principia …」の次は Mathematica しかなく、介入の余地がない
人間の文章を校正させただけほとんど乗らない。大半の語が人間のものだから
大幅な編集・言い換え・翻訳消えうる
完全な書き換え消える

記事の著者はこう懸念を述べています。

学校や職場が検出結果を証拠として濫用する未来が容易に想像できるだけに、この但し書きがどこまで読まれるかは気掛かりです。

5.3 コードと翻訳の扱い

コード: 正確さが要求される箇所には透かしを適用しないと明言されています。2 + 2 = の次に来るべきトークンは一つしかないので、そもそも介入しない。コード中のコメントのような任意性のある箇所では機能しうるが、コード自体への影響は無視できる程度、とのこと。

翻訳: 逆に、Claude に翻訳させた文章には透かしが入ります。翻訳では全ての語を Claude が選んでいるからです。

混同注意: 「翻訳で透かしが消える」という話は、透かし入りテキストを別の手段で翻訳した場合の攻撃（CWRA）を指します。Claude 自身に翻訳させる場合とは逆です。

5.4 個人の追跡には使われていない

研究の世界には「誰が生成したか」（ユーザー ID など）を埋め込むマルチビット型もありますが、Claude はその方向ではありません。

公式ブログは、透かしにも鍵にも個人・組織・チャットを特定する情報は含まれないと明言しています。「Claude が関与したか否か」の 1 ビットに徹する設計です。

なお画像などのファイルには、透かしではなく C2PA（カメラメーカーや写真編集ソフトが使う業界標準）のメタデータを付けるとのことです。こちらはファイル自体を変更しません。

この組織は、Claude Code が生成した日本語テキストを公開リポジトリと GitHub Pages に大量に出しています。 透かしの対象期間に入ってからの成果物には、原理上マークが乗っています。

6.2 何が起こりうるか

#論点評価
1納品物が「AI 生成」と判定されうるSIer の文脈では現実的な懸念。検出結果は「Claude が関与した尤度」でしかないが、受け取る側がそう読むとは限らない
2コードは影響が小さい公式が「正確さが要求される箇所には適用しない」と明言。.claude/hooks/ の実装や IaC はほぼ無関係
3設計書・レポート・ダイジェストは対象任意性の高い文章なので印が乗る。本組織の成果物の大半がこちら
4日本語では薄い可能性がある日本語はトークンが細かく刻まれ、次が文脈で決まりがち（「透か」の次は「し」）。揺らぎが少ない＝埋め込みにくい。ただし未実測

6.3 今すぐ何かを変える必要はない、と判断する理由

  1. 検出 API が未公開なので、自組織の成果物で実際に検出されるか試せない
  2. 日本語での実効性が未知（§6.2 #4）
  3. そもそも「AI で作っている」ことを隠していない組織である（README にも Skill 名にも明記されている）

7. 採用候補

(AX) 外部公開の確認観点に「AI 関与の判定可能性」を追加する — ⬜ 優先度 低

既存の候補 A（外部公開を伴う操作の確認ルールを明文化する）に軸を 1 本足す提案。

現在の候補 A は「社名・内部 URL・顧客情報・本番環境情報が混ざっていないか」という情報漏洩の観点だった。そこに次を加える。

この成果物が「AI 関与あり」と判定されうることを、出す前に承知しているか。

やること（候補 A を実装する際に一緒に書く、1 行の追加）:

  • 顧客納品物・外部公開物には、AI を使った旨を必要に応じて明示する（隠さない）
  • 検出結果を「AI が書いた証拠」として扱う/扱われることへの反論材料を用意しておく（§5.2 の公式見解）

コスト: 小（候補 A のチェックリストに 1 項目） 判断に必要な情報: 検出 API が公開されてから、自組織の日本語成果物で実際に検出されるかを測る

不採用にしたもの

透かしを消す方向の対処 — ❌ 不採用

言い換えや書き換えで消せることは公式も認めているが、本組織にそうする動機がない。AI を使っていることを隠していない以上、消す作業はコストにしかならない。
